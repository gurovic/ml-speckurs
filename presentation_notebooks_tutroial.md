# Presentation-ноутбуки на уроке: памятка для учителя

В папках теории рядом с методическим ноутбуком лежит файл `*_presentation.ipynb`.  
Это **сценарий урока у доски**, а не самоучитель.

| Файл | Для кого | Как читать |
|------|----------|------------|
| `Урок_N_….ipynb` (теория) | учитель при подготовке; ученик, который повторяет или пропустил | полный рассказ |
| `*_presentation.ipynb` | учитель **на уроке** | вопросы → демо → короткие выводы |
| `Тест_к_теории.ipynb` | ученик после теории | короткая проверка **только по core**; стандарт изготовления: `.cursor/skills/ml-lesson-workflow/theory-tests.md` |
| практика (`Урок_{N+1}_…`) | ученик на следующем занятии | задания с баллами |

Методичку на проектор обычно **не** выводят целиком: там много текста, который удобнее говорить голосом.

---

## Идея presentation

1. **Вопросы** (`**Обсудим:**`) — пауза, ответ класса, короткое обсуждение.
2. **Демо** — таблица, формула, график, 5–15 строк sklearn.
3. **Вывод** (отдельная ячейка `> **Вывод.** …`) — зафиксировать на доске / в тетради то, к чему пришли.

Ритм может чередоваться: вопрос → код → вопрос по картинке → вывод. Не обязательно сначала все вопросы, потом весь код.

Что **не** делать на уроке:

- не зачитывать абзацы из методички вместо диалога;
- не открывать вывод в той же ячейке, что вопрос (пропадёт пауза);
- не крутить test «ещё разок», если в сценарии уже выбран финальный прогон.

## Способ 1. Обычный Jupyter / JupyterLab (самый простой)

Подходит, если не хочется ставить расширения.

1. Откройте `*_presentation.ipynb` в JupyterLab или Jupyter Notebook.
2. Подключите проектор / демонстрацию экрана.
3. Увеличьте масштаб интерфейса (браузер Zoom или настройки Jupyter).
4. Идите сверху вниз: `Shift+Enter` — выполнить текущую ячейку и перейти дальше.
5. На вопросах **остановитесь**, не запускайте следующую ячейку с выводом, пока класс не ответил.
6. Код с графиками запускайте при всех — пусть цифры и картинки появятся «вживую».

Полезные привычки:

- перед уроком один раз прогоните весь ноутбук (`Run All`), чтобы не ловить сюрпризы с библиотеками;
- если ячейка длинная, сверните код (синий треугольник слева в JupyterLab) и покажите только вывод/график;
- держите методичку открытой на втором мониторе или в соседней вкладке — туда смотрите вы, не класс.

## Способ 2. RISE — ноутбук как живые слайды

RISE показывает ячейки как презентацию Reveal.js, при этом код **по-прежнему запускается**.

Установка (JupyterLab / Notebook 7):

```bash
pip install jupyterlab-rise
```

Подготовка (один раз на файл):

1. Откройте Property Inspector (шестерёнка / `Ctrl+Shift+U`).
2. Для каждой ячейки задайте **Slide Type**:
   - `Slide` — новый слайд (вопрос, новый раздел, важный график);
   - `Fragment` — появление по клику на том же слайде (удобно для `> **Вывод.**` после паузы);
   - `Skip` — не показывать как слайд (редко нужно);
   - `Notes` — заметки только для себя (speaker view).
3. Сохраните ноутбук.

На уроке:

1. Кнопка «Render as Reveal Slideshow» или горячая клавиша (**Alt+R** / **Ctrl+R** — смотрите подсказку в своей версии).
2. Вперёд — пробел (или стрелки); назад — `Shift+Пробел`.
3. На слайде с кодом — `Shift+Enter`, как в обычном ноутбуке.

Типичная разметка для наших presentation:

| Ячейка | Slide Type |
|--------|------------|
| `## N. Заголовок` + вопрос | `Slide` |
| код / график | `Slide` или тот же слайд + `Fragment` |
| `> **Вывод.**` | `Fragment` (после обсуждения) |

## Способ 3. Cursor / VS Code

Если ведёте урок из редактора:

1. Откройте `*_presentation.ipynb`.
2. Выберите kernel Python с sklearn / matplotlib.
3. Режим фокуса: Zen Mode / полный экран окна.
4. Увеличьте `Editor: Font Size` на время урока.
5. Запускайте ячейки по одной; markdown с вопросом держите в центре экрана.

Минус: слайдового режима как в RISE нет. Плюс: удобно править текст прямо на уроке, если вопрос «не зашёл».

---

## Способ 4. Экспорт в HTML-слайды (без живого ядра)

Если нужен только просмотр уже посчитанных картинок (олимпиада, гостевой ноут без Python):

```bash
jupyter nbconvert --to slides путь/к/файлу_presentation.ipynb --post serve
```

Или без `--post serve` — откройте получившийся `.slides.html` в браузере.

Минус: нельзя заново обучить модель «здесь и сейчас». Для нашего курса обычно хуже, чем способы 1–2.

## Как вести 45–90 минут

Примерный каркас (подстройте под пару теория/практика):

1. **Старт (3–5 мин)** — шапка presentation: о чём урок, куда смотреть полную теорию.
2. **Основная лента** — разделы `## N.` по сценарию; не обязательно пройти все `*` повышенной сложности.
3. **Демо sklearn** — коротко: «вот как это выглядит в коде», без чтения каждой строки вслух.
4. **Фиксация** — ученики записывают формулировки из ячеек **Вывод** (или вы выносите их на доску).
5. **Хвост** — устные вопросы из чек-листа в конце presentation / короткий тест отдельно.

Если времени мало:

- пропускайте разделы без демо, оставляя один сильный вопрос + вывод;
- звёздочные темы (`## … *`) — «в методичке», не на доске;
- график важнее простыни `print`.

## Технический чек-лист перед уроком

- [ ] Установлены `numpy`, `pandas`, `scikit-learn`, `matplotlib` (и то, что импортирует конкретный ноутбук).
- [ ] Kernel запускается, `Run All` на presentation проходит без красных traceback.
- [ ] Шрифт на проекторе читается с последних парт.
- [ ] Методичка открыта у вас, presentation — у класса.
- [ ] Если используете RISE — слайд-типы проставлены и вы один раз прощёлкали шоу.

## Частые вопросы

**Можно ли править presentation под свой класс?**  
Да. Вопросы можно переформулировать. Номера `## N.` лучше не ломать: на них ссылаются упражнения и практика.

**Что показывать ученику, который болел?**  
Методический ноутбук теории + при желании тот же presentation как «оглавление урока».

**Нужно ли заливать presentation в DS-course?**  
Решает команда курса отдельно от статуса теории. Пока в `status.md` presentation сам по себе не отмечен.

**Где взять новые presentation?**  
Их собирают из методической теории по skill `generate-presentation-notebook` (суффикс `_presentation` в имени файла).
